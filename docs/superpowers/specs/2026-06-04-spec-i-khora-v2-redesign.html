1Branch — corrected to real Firecracker semantics

B1/B2. v1 said: "`cp --reflink` a live memfile, parent keeps running, <50ms." All four reviewers (Codex web-searched the Firecracker docs to confirm) flagged this as impossible: Firecracker's only snapshot path is Pause → CreateSnapshot → restore, and loaded memory files must be immutable. You cannot reflink the memory of an un-paused guest and get a coherent image.

5Corrected decisions + two new

L7-D2 (corrected · B8) — new khora-pool for VM lifecycle (warm-set per template_id, exclusive checkout, reset-or-destroy). The gRPC life-runtime-pool is a channel pool, not a VM-resource pool; only its CircuitBreaker is reused, for the khorad↔envd link.
L7-D9 (new · B7) — cross-host resume only within a CPU-template-normalized host pool (fixed TSC, normalized CPUID). Default acceptance is same-host; cross-pool is gated and rejected, not attempted, outside the pool.
L7-D10 (new · S13) — Khora is the one isolation primitive; Aegis is redefined as its policy layer (owns EgressPolicy content, capability scopes, attestation), not a second sandbox. praxis becomes InProcessKhora dev-mode behind the one KhoraSession interface. No overlapping isolation code.

7Build-vs-buy — the honest answer

S11/S12. v1's only stated reason to rebuild E2B was "Rust vocabulary." The principal chose build; the honest irreducible reasons:

  1. Branch lives in the VMM control path. The divergence hook + diff-snapshot reflink + pause-window orchestration are operations E2B's control plane doesn't expose.
  2. Per-action custody + event sourcing at the orchestrator — binding AnimaCustody and emitting khora.* per RPC is deepest at the orchestrator, not bolted onto a foreign Go control plane.
  3. One-language operational surface (pool/breaker/saga already Rust) — real, but explicitly secondary.
  4. The substrate is the long-term product.
Honesty clause (kept from the review). e2b-dev/infra (Apache-2.0) is the reference for the UFFD page server, template pipeline, and jailer setup — read, not blindly rewritten. And the wrap-E2B fallback stays live: if Sub-R or Sub-B2 prove the UFFD page server is disproportionately costly to build correctly, wrapping E2B's orchestrator (and emitting the cross-substrate events over it) is the documented retreat — the fabric needs event emission at the orchestration layer, not necessarily our own khorad. Sequencing (S12): Spec E (17%) and M9 remain the acknowledged critical path; Sub-E + the GPU pool stay sequenced behind Spec E even within this build.
