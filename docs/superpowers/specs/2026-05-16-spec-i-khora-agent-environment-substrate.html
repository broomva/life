SPEC I · KHORA · v1 · DRAFT · Life Agent OS · substrate primitive

Khora — the receptacle where agents become

The environment substrate of the Life Agent OS: a Firecracker-backed habitat that hosts every agent — snapshotable, branchable, identity-bound, event-sourced. Not the agent. Not the shield around it. The place in which the agent acts, fails, forks, persists, and is metered.

The thesis in one line. Most agentic problems are not about the agent — they are about the environment. filesystem + bash is the right starting interface; the hard part is making the environment that runs it fast to spawn, cheap to idle, safe to share, possible to snapshot, and cheap to fork. Vercel Sandbox and E2B prove the market; neither was built to be the body of an operating-system-grade agent. Khora is. It is the soma module's sibling — where anima says who, khora says where.

0The name — and why khora, not Aegis

The first instinct was Aegis — Athena's shield. Wrong frame. Aegis is the protective wall: capability attestation, secret management, sandbox policy. That primitive stays in the roadmap. What this spec builds is the layer underneath the shield: the habitat itself, the room the agent lives in. The Greek for that is χώρα.

…there is a third nature, which is space (χώρα), and is eternal, and admits not of destruction, and provides a home for all created things… — Plato, Timaeus 52a–b. The receptacle of becoming — neither the eternal Forms nor the sensible particulars, but the third kind: the place in which forms imprint into matter.

The pairing with Anima (Latin: soul, the agent's immutable origin + mutable belief) is exact. Anima alone is a static document. Khora alone is an empty room. Together: an agent that exists somewhere, doing something, accumulating a history. Khora is where the agent's becoming actually happens.

shipped active this spec planned

Greek × Latin cross-lineage is deliberate and already established in Life: soma/haima/praxis/nous (Greek) sit beside anima/vigil (Latin). Khora extends the Greek line. No crate, doc, or trademark collision in the agent/infra space.

1Anima · Soma · Khora — complement, not conflict

A precise distinction the spec rests on, because three different things share the word "identity":

ConcernWhere it livesOwner
What is an identity — soul, belief, DID, rotation semanticscrates/anima/anima-core/Anima (the abstraction)
How does an identity sign — trait surface, 6 backendscrates/anima/anima-identity/Anima (one impl bound to soma)
Where do the keys physically live — a daemon? TPM? Ledger? Vault? RAM?varies — soma is one optionthe chosen backend
Where does the agent act — exec, fs, branch, persist, failcrates/khora/Khora (this spec)

Soma is not a competing identity system. AnimaCustody is a trait; SomaCustody is one of six implementations of it — the one whose transport is the soma daemon's admin UDS. The agent loop only ever sees the trait; the operator picks the backend per deployment.

Khora binds an Arc<dyn AnimaCustody> at create-time (decision L7-D5). Whether that's SomaCustody, VaultTransitAnima, or TpmAnima is the operator's choice — Khora depends on Anima's trait, never on soma directly.

2The problem — the soft-sandbox ceiling

Life's agent loop today calls a soft sandbox. praxis-core ships FsPolicy (path-string boundary check) and SandboxPolicy (command-name allowlist). Both are advisory — they assume a cooperating agent. The core/life/CLAUDE.md "Known gaps" set names it directly:

✗ No OS-level isolation. A buggy or hostile tool call reads anything the daemon UID can read.
✗ Network policy declared, not enforced. policy.yaml egress rules don't reach the kernel.
✗ Mount trait unimplemented. No real volume model.
✗ No pause / resume. Long-horizon agents (>1h) retry-from-scratch or block the host.

The soft sandbox was correct for v0.1 — it proved the loop. It is the wrong substrate for multi-tenant hosting (chatOS user sessions, mission-control third-party skills, the freelance/_template Life Module pattern), for long-horizon work, for speculative exploration, and for any deployment where agent code is not fully trusted. Spec I builds the hard substrate.

4Substrate decision — why Firecracker

Every credible 2025–2026 agent-sandbox provider converged on the same stack: Firecracker microVMs + UFFD lazy memory restore + per-host orchestrator + guest gRPC daemon. The comparison is not close for long-running, snapshotable agent loops.

SubstrateCold bootSnapshot/restoreOverheadFit for long agent loops
Firecracker~125msp50 3–8ms, ~28ms warm-pool<5MiB/VM✓ the only viable primary
Cloud Hypervisor~150mssimilar<10MiB✓ GPU sidetrack (VFIO)
gVisor~50msno prod C/R18% typ / 125% worst✗ can't resume cross-host
wasmtime (WASI)<1mscomponent-model~0✗ as outer (no subprocess); ✓ as inner

Anthropic's own Claude Code bash tool uses neither a microVM nor gVisor — it's anthropic-experimental/sandbox-runtime (macOS Seatbelt + Linux bubblewrap + a Unix-socket proxy), bash-scope only. Server-side Computer Use substrate is undisclosed. E2B (e2b-dev/infra, OSS) = Firecracker + UFFD, p50 78ms create. Vercel Sandbox (GA 2026-01-30) = Firecracker on Amazon Linux 2023, iad1-only, no GPU, max 4 inbound ports.

6The ACI surface — five primitives

Five ACI primitives. That's the whole agent-facing interface. Everything else — browsers, Jupyter, GPU compute, MCP servers, language servers — runs inside via Exec. This is the SWE-agent + Computer Use convergence: a small set the model already uses well, not a tool zoo.

Exec bash. cmd, args, env, stdin, cwd, timeout → stream(stdout|stderr|exit). The universal escape valve.
FsRead path, byte_range? → bytes.
FsWrite path, bytes, mode, create_if_missing → ack.
FsEdit hashline. Blake3 content-addressed line edits (the Praxis pattern) — verifiable atomic edits with collision detection.
FsList glob + grep + inotify-watch in one verb.
+ lifecycle Create · Pause · Resume · Branch · Stop  + policy UpdateNetPolicy · MintEgressToken  + obs Logs · Metrics
The KhoraSession trait (Rust) 
#[async_trait]
pub trait KhoraSession: Send + Sync {
    fn khora_id(&self) -> KhoraId;
    fn anima_did(&self) -> &str;
    fn parent(&self) -> Option<KhoraId>;

    // ACI — 5 primitives
    async fn exec(&self, req: ExecRequest) -> KhoraResult<ExecStream>;
    async fn fs_read(&self, path: &Path, range: Option<ByteRange>) -> KhoraResult<Bytes>;
    async fn fs_write(&self, path: &Path, bytes: Bytes, mode: FsWriteMode) -> KhoraResult<()>;
    async fn fs_edit(&self, path: &Path, edit: HashlineEdit) -> KhoraResult<FsEditResult>;
    async fn fs_list(&self, path: &Path, pat: Option<Glob>, recursive: bool) -> KhoraResult<Vec<FsEntry>>;

    // Lifecycle — 5 primitives
    async fn pause(&self) -> KhoraResult<Snapshot>;
    async fn resume(snap: Snapshot, anima: Arc<dyn AnimaCustody>) -> KhoraResult<Arc<dyn KhoraSession>>;
    async fn branch(&self) -> KhoraResult<Arc<dyn KhoraSession>>;
    async fn stop(&self) -> KhoraResult<()>;

    // Policy + observability
    async fn update_net_policy(&self, p: EgressPolicy) -> KhoraResult<()>;
    async fn mint_egress_token(&self, r: MintEgressTokenRequest) -> KhoraResult<EgressToken>;
    async fn logs(&self, range: LogRange) -> KhoraResult<LogStream>;
    async fn metrics(&self) -> KhoraResult<KhoraMetrics>;
}

Template pipeline

A Khorafile (Dockerfile-shaped) builds to a content-addressed snapshot triple stored in Lago's blob CAS — every template version hashed, every restore replayable from a known base.

7Branch — the novel wedge

Branch is the one primitive no comparison product ships. Vercel and E2B have snapshots; neither has fork-a-running-sandbox-cheaply. Khora does, because it already lives in the Life journal-branching model (BranchId): a child shares the parent's rootfs.ext4 (read-only) + a CoW overlay, and clones the parent memfile via cp --reflink=always on XFS/Btrfs. Target: <50ms.

Speculation becomes economics. Agent at a decision point → Branch × 4 → run all four paths to depth N → measure → keep best, Stop the rest. On a 4-vCPU class at ~30s/branch that's ≈ $0.04 for a 4-way speculative exploration. Today, on Vercel/E2B, this is unaffordable (4 full snapshot+create cycles, parent stalls). Khora makes it a routine move — and Haima bills per-branch, so the operator can budget speculation.

8Life integration — cross-substrate by construction

A khora is not a remote service the agent calls — it is a surface the agent has, like its anima. Every running khora emits to all five existing substrates in parallel. This is the wedge no standalone sandbox can match: identity, event-sourcing, metering, and observability are siblings, not bolt-ons.

Identity binding & egress brokering

Raw API keys never enter the khora. MintEgressToken issues a short-lived bearer scoped to the bound anima's Tier-User capability; lifegw injects the real secret at the egress-proxy edge (the Vercel forwarding-rule pattern, sharpened to per-mint scope + revocation). First compromise leaks a 60-second token, not a key.

let khora = khora_client.create(CreateRequest {
    template_id:   "claude-code-base:v3",
    vcpus: 4, ram_mb: 8192, timeout: Duration::from_secs(3600),
    anima_did:     "did:key:zDn…",                 // who runs inside
    egress_policy: EgressPolicy::AllowList(vec!["github.com", "*.anthropic.com"]),
    haima_budget:  BudgetCap::CpuSeconds(10_000),  // hard ceiling
    parent_session: Some(session_id),              // for branch lineage
    ..Default::default()
}).await?;

9Locked design decisions — L7-D1 .. L7-D8

Invariants downstream sub-phases inherit and cannot relitigate without a spec amendment (the Spec D / Spec E pattern).

L7-D1 · Substrate

Firecracker primary; Cloud Hypervisor sibling for GPU; wasmtime inner

Only Firecracker has production snapshot/restore at agent scale. gVisor's 18–125% syscall tax and no-prod-C/R disqualify it. CH sibling pool for VFIO GPU only. wasmtime for sub-ms read-only inner ops.
L7-D2 · Orchestration

Per-host Rust khorad; Nomad/K8s schedules hosts only

Reuses life-runtime-pool + breaker + saga + tonic-UDS. Per-host blast radius, not cluster-wide. Rust, because the rest of life-runtime is.
L7-D3 · Templates

Lago blob CAS — template_id = sha256(manifest)

{rootfs.ext4, memfile, snapfile} triple, SHA-256+zstd, replayable from a known hash. Provenance joins to journal events; multi-region replication is by-hash pull.
L7-D4 · ACI surface

Five primitives + lifecycle + policy

Exec · FsRead · FsWrite · FsEdit · FsList + Create/Pause/Resume/Branch/Stop + UpdateNetPolicy/MintEgressToken. Anything else runs inside via Exec.
L7-D5 · Identity

Every khora binds Arc<dyn AnimaCustody> at create

No outbound calls without a minted egress token (Tier-User cap, Spec D). Raw secrets never enter the VM. Opt-out is not available — secured-by-default.
L7-D6 · Branch

First-class; CoW rootfs + memfile reflink clone

The wedge no competitor ships. <50ms target. Open risk: memfile-CoW under concurrent writes; fallback full-copy (~4s/GiB). Stress-tested in Sub-F.
L7-D7 · Events

Every action → khora.* Lago event; every second → Haima meter

Full replay via lago replay --tree. Per-branch billable. Vigil OTLP spans parent-linked to the agent tick.
L7-D8 · Conformance

khora-conformance is the public contract

One battery validates InProcessKhora + FirecrackerKhora + RemoteKhora. Third parties implement Khora-compat backends and prove compliance.

The non-wedges — honest accounting
  • Cold start. Day-1 will lag E2B's 78ms p50. Target: match within 30% by Sub-B. Not a from-scratch win.
  • Template ecosystem. Empty on day 1; E2B has hundreds. Catalog scale is a year-2 problem.
  • Substrate engineering. We use Firecracker well; we are not out-engineering AWS on the VMM.
  • Inbound exposure. Vercel/E2B expose *-{id} URLs. Khora's case is agent→outbound; inbound is carved out (Khora-Sub-G if demand emerges).
The product story. "Vercel Sandbox is a serverless function with a longer leash. E2B is a code-interpreter-as-a-service. Khora is an agent operating-system kernel — your agent isn't a guest; the sandbox is part of the agent's body." Khora is the Life substrate first; the standalone product story emerges if Life adoption proves it.

12Phasing — six sub-waves

Mirrors Spec D Wave 1–4 and Spec E E-Sub-A..F: trait + first backend → real backend → transport → cross-cutting → end-to-end → novel primitive. Critical path A → B → C → E ≈ 15 working days; ~17 days wall-clock with parallel dispatch.

13Acceptance & open questions

Spec I ships when

  1. cargo test -p khora-conformance green against InProcess + Firecracker + Remote.
  2. claude-code-base template + BRO-1013 live-Anthropic smoke runs inside Khora; khora.* events visible via lago replay --tree.
  3. Warm-pool restore p50 < 100ms; cold boot p50 < 200ms (khora-bench).
  4. Pause 24h → resume on a different host → complete the task; journal contiguous across the boundary.
  5. 4-way speculation example runs to depth 5, keeps best; Haima shows 4 branches billed; Lago shows 4 sub-journals.
  6. One Exec → Lago events + Haima meter + Vigil span (tick-parented) + Anima metadata.
  7. A freelance/_template tenant runs their own khorad + soma-backed custody; conformance green.
  8. CLAUDE.md "Known gaps" closed: OS-isolation, network-enforcement, Mount.

Open questions (SPEC-I-DEVIATION candidates)

1 · Memfile CoW concurrency. If reflink + concurrent parent writes is unstable, fallback to full memfile copy. Branch still works; latency degrades. Sub-F stress test; decision deferred to data.
2 · CH GPU pool gating. Lands with Spec E E-Sub-C (CUDA). Pulled in as a hook only. Deferred to Spec E coordination.
3 · Mount trait. First-class MountVolume RPC or Exec-of-mount? Sub-A decision.
4 · Praxis migration. Default: InProcessKhora wraps praxis-tools as dev-mode, so dev workflows don't break. Deprecation timeline open.
5 · Inbound ports. Currently no — agent case is outbound. Carved out as Khora-Sub-G if demand emerges.
6 · CRIU cross-host migration. FC snapshots are CPU-feature-pinned. Feature-pinned host pools vs CRIU. Year-2.
